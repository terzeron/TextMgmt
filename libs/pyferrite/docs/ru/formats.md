# Особенности каждого формата

## `.npy`

Полная поддержка: все дескрипторы numpy, для которых в крейте есть `DType`, оба
порядка байт, C- и Fortran-порядок, структурированные типы (записи) и массивы
объектов, элементы которых разбираются рекурсивным запуском машины pickle.

Заголовки версий 1, 2 и 3 читаются; записывается версия 1, а если заголовок
превысил бы 65 535 байт — версия 2. Заголовок дополняется так, чтобы данные
начинались на границе 64 байт, как это делает numpy.

Массивы записей по умолчанию превращаются в [`Frame`](types.md#таблицы).
Установите `ReadOptions::keep_record_arrays`, чтобы получить исходный
структурированный массив.

## `.npz`

ZIP-архив из элементов `.npy`, читаемый и записываемый собственной реализацией
ZIP (включая ZIP64 и CRC-32). Поддерживаются элементы и без сжатия, и со
сжатием deflate.

В numpy нет понятия вложенности, поэтому вложенные словари при записи
разворачиваются с разделителем `/` и восстанавливаются при чтении. Значение
`{"grp": {"inner": ...}}` становится элементом с именем `grp/inner.npy`, который
`np.load(...)["grp/inner"]` читает напрямую. Поэтому сами ключи не могут
содержать `/`.

Одиночный массив записывается как `arr_0`, список — как `arr_0`, `arr_1`, …,
в точности как в `numpy.savez`.

## `.pkl` / `.pickle`

Протоколы с 0 по 5, включая кадрирование, мемоизацию, коды расширенного реестра
и коды внеполосных буферов протокола 5.

Виртуальная машина **никогда не исполняет Python**. Конструкторы разрешаются по
белому списку, охватывающему numpy, torch, `collections` и `_codecs`; `os`,
`sys`, `subprocess` и им подобные отвергаются, если не установлен
`ReadOptions::allow_unknown_globals`. Всё остальное становится инертным
`PyObject`, хранящим имя класса и его аргументы.

Массивы numpy распознаются во всех трёх видах, в которых их порождает numpy:
классическая последовательность `_reconstruct` плюс `BUILD`, путь `scalar` для
нульмерных значений и путь `_frombuffer`, которым numpy 2.x пользуется под
протоколом 5.

При записи по умолчанию используется протокол 4; протокол 2 наиболее переносим
между старыми версиями Python. Кодирование массивов повторяет собственное
кодирование numpy, поэтому `pickle.load` возвращает настоящий `np.ndarray`, а
не суррогат.

## `.pt` / `.pth`

Формат ZIP, появившийся в torch 1.6: `archive/data.pkl` рядом с одним сырым
блоком на каждое хранилище в `archive/data/`. Постоянные идентификаторы вида
`('storage', torch.FloatStorage, key, location, numel)` разрешаются через эти
блоки. Обрабатываются и непрерывные, и тензоры с шагами; вторые собираются по
записанным шагам.

Записанные файлы содержат элементы `data.pkl`, `version` и `byteorder` и
используют `torch._utils._rebuild_tensor_v2` — именно то, чего ждёт
`torch.load`. Поток pickle всегда пишется по протоколу 2, как это делает
`torch.save`, независимо от `WriteOptions::pickle_protocol`: безопасный
загрузчик `weights_only`, который `torch.load` применяет по умолчанию начиная с
PyTorch 2.6, отвергает коды операций протоколов 4 и 5.

**Устаревшие контрольные точки** — формат до версии 1.6 из пяти склеенных
pickle с таблицей хранилищ следом — **не поддерживаются**. При чтении возникает
ошибка, которая называет проблему и предлагает
`torch.save(obj, path, _use_new_zipfile_serialization=True)`. Это сознательный
отказ, а не попытка угадать: тихо прочитать веса неправильно хуже, чем упасть.

## `.joblib`

joblib записывает pickle, в котором массивы заменены объектами
`NumpyArrayWrapper`, а сырой буфер идёт сразу следом в том же потоке байт.
Читатель чередует разбор соответствующим образом и учитывает выравнивающее
дополнение, которое вставляют joblib 1.2 и новее.

Читаются контейнеры без сжатия, а также zlib и gzip. bz2, xz и lz4 — нет:
каждый из них потребовал бы компрессора, который нельзя получить без чужого
кода, поэтому они дают понятную ошибку с предложением `compress=0`, `'zlib'`
или `'gzip'`.

## `.h5` / `.hdf5`

Подмножество на чистом Rust. То, что намеренно сужено, честно описано, а не
приблизительно изображено.

### Чтение

| Область | Поддерживается |
|---|---|
| Суперблок | версии 0, 1, 2, 3 |
| Заголовки объектов | версии 1 и 2, с блоками продолжения |
| Группы | B-деревья таблиц символов (классические) и сообщения-ссылки (новый стиль) |
| Размещение данных | непрерывное, компактное, чанками (индекс — B-дерево версии 1) |
| Фильтры | deflate, shuffle, fletcher32 |
| Типы данных | целые, вещественные, битовые поля, перечисления, строки фиксированной длины |

### Запись

Суперблок версии 0, заголовки объектов версии 1, группы с таблицами символов и
непрерывные наборы данных с прямым порядком байт, с произвольной вложенностью.
Файлы читаются `h5py`, `h5ls` и эталонной библиотекой на C.

### Не поддерживается

Строки переменной длины, составные и массивные типы данных, ссылки на объекты,
виртуальные и внешние наборы данных, атрибуты и любые фильтры, кроме трёх
перечисленных. Встреча с ними даёт `Error::Unsupported` с названием
возможности.

Логические массивы записываются как беззнаковые 8-битные целые, потому что в
HDF5 нет собственного логического типа; h5py для тех же данных пишет
перечисление, которое эта библиотека читает обратно как `U8`. Комплексных чисел
в подмножестве записи нет — приведите их к другому типу или возьмите другой
формат.

## Определение формата

`read` смотрит на ведущие байты: `\x93NUMPY` для `.npy`, `\x89HDF\r\n\x1a\n`
для HDF5, `0x80` для pickle и `PK\x03\x04` для ZIP, который затем различается по
имени первого элемента: элемент `.npy` означает `.npz`, любой другой — torch.
И только если это неубедительно, решает расширение. `ReadOptions::format`
перекрывает всё.
