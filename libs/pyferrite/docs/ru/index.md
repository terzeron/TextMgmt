# pyferrite — документация

`pyferrite` читает и пишет форматы файлов, которые порождает Python-код для
машинного обучения, — из Rust и без единой строки на C.

## Установка

```toml
[dependencies]
pyferrite = "0.0.2"
```

Версия `0.0.2` — ранний выпуск. До `0.1.0` публичный API ещё может
измениться.

### Флаги возможностей

| Флаг | По умолчанию | Что даёт | Цена |
|---|---|---|---|
| `deflate` | **включён** | Сжатые элементы `.npz`, `.joblib` в обёртке gzip и zlib, фильтр deflate в HDF5 | одна зависимость, `miniz_oxide` (чистый Rust) |
| `polars-interop` | выключен | Преобразование `Frame` ⇄ `polars::DataFrame` | тянет `polars` |

Сборка без всего, кроме стандартной библиотеки и `ndarray`:

```toml
pyferrite = { version = "0.0.2", default-features = false }
```

Несжатые файлы в этой конфигурации работают по-прежнему; сжатый вернёт
`Error::Compression`, а не выдаст неверные числа.

## Принципы, на которых построена библиотека

**Никакого чужого кода.** Ни C, ни C++, ни FFI, ни заранее собранных бинарников.
Каждый формат, каждая контрольная сумма, каждое представление числа с плавающей
точкой и вся виртуальная машина pickle реализованы внутри этого крейта. Именно
поэтому библиотека работает на голом железе и во встраиваемых окружениях, где
доступен только компилятор Rust.

**Всё, что вы получаете, находится во владении вызывающей стороны.** Никаких
заимствованных представлений отображённого в память файла, поэтому для правки
весов на месте достаточно `let mut`. У каждого типа массива есть и явный
аксессор `as_*_mut()`.

**Сбои — громкие.** Несовпадение формы, выход за диапазон при приведении,
обрезанный файл или тип данных, который писатель не умеет выразить, — это
`Err`, а не тихо испорченный файл.

**Pickle никогда не исполняется.** См. [errors.md](errors.md#безопасность-pickle).

## Быстрый старт

```rust,no_run
use pyferrite::prelude::*;

// Читаем что угодно: формат определяется по сигнатуре, расширение — запасной
// вариант.
let mut model = read("checkpoint.pt")?;

// Обходим все массивы дерева, какой бы ни была вложенность.
for (name, array) in flatten_arrays(&model) {
    println!("{name}: {:?} {:?}", array.dtype(), array.shape());
}

// Правим на месте.
for a in model.arrays_mut() {
    if let Some(w) = a.as_f32_mut() {
        w.iter_mut().for_each(|x| *x *= 0.5);
    }
}

// И записываем обратно уже в другом формате.
write("checkpoint.h5", &model)?;
# Ok::<(), pyferrite::Error>(())
```

## Поддержка форматов

| Расширение | Чтение | Запись | Поток на чтение | Поток на запись |
|---|---|---|---|---|
| `.npy` | да | да | да | да |
| `.npz` | да | да | да | нет |
| `.pkl`, `.pickle` | да | да | нет | нет |
| `.pt`, `.pth` | да (zip-формат) | да | нет | нет |
| `.joblib` | да | да | нет | нет |
| `.h5`, `.hdf5` | подмножество | подмножество | да | да |

Потоковая обработка невозможна там, где полезные данные перемешаны с графом
объектов: pickle нужно пройти с самого начала, чтобы понять, где что лежит.
Точное подмножество HDF5 описано в [formats.md](formats.md).
