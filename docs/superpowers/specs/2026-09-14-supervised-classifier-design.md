# 지도학습 기반 도서 자동분류 설계

- 날짜: 2026-09-14
- 상태: 승인됨 (v2 + 개발 중 반영분)
- 대상: `backend/book_classifier.py` 판정 로직 전면 교체
- 앞 설계: `2026-09-12-corpus-lexicon-classification-design.md` (이 문서가 대체한다)

## 1. 왜 바꾸는가

앞 설계의 어휘 사전 + Complement Naive Bayes 는 목표에 못 미쳤다.

| 방법                        | 판정률    | 정답률    |
| --------------------------- | --------- | --------- |
| CNB 파일명                  | 27.7%     | 90.0%     |
| 기존 전체 조합 + 서점       | 50.8%     | 85.8%     |
| **선형 모델 (본문+파일명)** | **92.7%** | **90.0%** |

같은 파일명, 같은 정보로 강제 판정했을 때 CNB 는 53.1%, 선형 모델은 82.1% 였다.
생성 모델과 판별 모델의 차이가 29%p 다. 목표 90/90 은 선형 모델에서 이미 넘었고,
그 수치는 `publisher` 없음, 불균형 보정 없음, 서점 없음, 튜닝 없음 상태의 값이다.

측정: 홀드아웃 47,164건, 카테고리 81개.

GPU 가 없어 트랜스포머 미세조정은 못 한다. 23만 건 레이블에 81개 클래스 주제 분류는
선형 모델의 강점 영역이라 필요도 없다.

## 3. 파일 배치

```
backend/classifier/
  __init__.py          공개 API — BookCategoryClassifier
  corpus.py            ES → 학습 데이터 수집
  features.py          필드별 특징 추출
  model.py             모델 로드·예측·확신도
  training.py          학습 + 평가
  reader.py            파일 직접 읽기 (ES 에 없을 때의 대비책)
  config.py            설정 스키마 + 기본값 + 상위 장르 매핑
  config.json          [데이터] 현재 설정
utils/classify_cli.py  CLI

/mnt/data/text/.classifier/
  model.joblib         [데이터] 학습 산출물. 저장소 밖에 둔다
```

설정 파일은 저장소에 둔다. 모델 파일은 안 둔다.

### 모델 파일은 books 볼륨에 둔다

`model.joblib` 은 100MB 단위다. 지금 저장소가 추적하는 파일 중 1MB 를 넘는 것이
하나도 없고, 재학습마다 새 사본이 쌓이면 `.git`(522MB)이 빠르게 커진다.

경로를 `TM_CLASSIFIER_MODEL` 환경변수로 받는다.

| 위치      | 값                                                     |
| --------- | ------------------------------------------------------ |
| 학습 머신 | `/mnt/data/text/.classifier/model.joblib`              |
| pod       | `/books/.classifier/model.joblib`                      |
| 미설정    | `backend/classifier/model.joblib` (테스트·단독 실행용) |

`books-pv` 가 호스트의 `/mnt/data/text` 를 pod 의 `/books` 로 마운트하므로
(`k8s/books-volume.yml`) 둘은 같은 물리 파일이다. 학습하면 pod 가 재시작할 때
새 모델을 읽는다. 이미지를 다시 굽지도, master 브랜치 작업 디렉토리로 복사하지도 않는다.

이 디렉토리는 loader 의 색인 대상 안에 있다. 문제되지 않는다. loader 는 확장자로
파서를 고르고 `joblib` 은 `supported_types` 에 없어 빈 결과를 돌려준다.
레이블 규칙(`^[1-9]_`)이 학습 오염도 따로 막는다.

백엔드 런타임은 `model.joblib` 만 읽는다. 학습은 백엔드 프로세스 밖에서 돈다.

## 4. 데이터는 ES 에서 온다

ES 는 inode 를 `_id` 로 써서 `/mnt/data/text` 의 모든 문서를 인덱싱해 두었다.
23만 6천 건을 45초에 긁는다. `/mnt/data` 는 회전 디스크라 파일을 직접 읽으면 몇 시간이다.

| 쓰는 곳            | 방법                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| 학습 데이터 수집   | `helpers.scan` 으로 인덱스 전체를 훑는다                                                        |
| 파일 하나 판정     | `_id` = inode 로 곧바로 집어 온다. 디스크를 안 읽는다                                           |
| inode 가 바뀐 경우 | `file_path` term 질의로 되찾는다 (`file_path` 는 keyword 타입이라 `.keyword` 를 붙이면 안 된다) |

### file_path 는 상대 경로다

loader 가 `file_path.relative_to(prefix)` 로 넣기 때문에 ES 의 `file_path` 는
라이브러리 루트 기준 상대 경로다(`3_무협/책.epub`). 절대 경로로 다루면 조용히 실패한다.

개발 중 실측: 이 가정을 틀리게 잡아 EPUB 58,766건을 열었는데 publisher 를 0건 얻었다.
예외도 로그도 안 났다. `읽음 58,766 / 값 있음 0` 이라는 숫자 하나가 유일한 신호였다.

그래서 두 곳에서 루트를 붙인다.

| 위치                                     | 하는 일                                  |
| ---------------------------------------- | ---------------------------------------- |
| `corpus.absolute_path()`                 | 학습 데이터의 상대 경로를 실제 경로로    |
| `BookCategoryClassifier._indexed_path()` | 판정할 절대 경로를 ES 질의용 상대 경로로 |

루트는 `config.json` 의 `corpus.library_root` 다(기본 `/mnt/data/text`).

### 레이블은 '숫자\_이름' 꼴만 쓴다

ES 에는 카테고리가 아닌 디렉토리도 색인돼 있다. 실측에서 `trash` 733건,
`.preview_cache` 46건, `_root` 10건이 레이블로 섞여 들어왔다.

제외 목록을 늘리는 대신 `^[1-9]_` 라는 긍정 규칙 하나로 거른다(`corpus.label_pattern`).
목록 방식은 새 운영 디렉토리가 생길 때마다 조용히 뚫린다.
이 꼴이면서 레이블이 아닌 `9_북스캔OCR` 만 `excluded_prefixes` 로 따로 뺀다.

### 포맷을 EPUB 으로 제한하지 않는다

ES 에는 EPUB 말고도 PDF, TXT, HWP, DOCX 등이 들어 있고 모두 본문 앞부분을 갖고 있다.
포맷마다 필드 품질이 고르지는 않다. 그래도 EPUB 으로 제한하지 않는다.
문서가 몇십 건뿐인 카테고리는 EPUB 만 남기면 학습 표본이 사라진다.
확장자는 그 자체가 특징 필드(`file_type`)이기도 하다.

### publisher 는 ES 필드로 추가한다

`dc:publisher` 는 전집 판정의 결정적 증거다. 을유문화사는 `2_을유세계문학전집` 의
98.6% 에 있고 상위 장르 `2_소설외국` 에는 0.0% 다.

ES 매핑에 `publisher` 를 추가하고(`backend/es_manager.py`), loader 가 색인할 때
EPUB 의 OPF 에서 읽어 넣는다. OPF 멤버 하나만 푸므로 본문을 다시 읽지 않는다.
기존 인덱스에는 `_ensure_publisher_field()` 가 매핑만 덧붙인다.

실측: EPUB 804건 표본에서 618건(77%)에 `dc:publisher` 가 있었다.
전체 58,766건이면 약 30분 걸린다(워커 2개, 회전 디스크).

아직 다시 색인하지 않은 문서는 값이 비어 있다. `collect --with-publisher` 가 그런
EPUB 만 골라 파일에서 읽어 메우고, 결과를 `<출력파일>.publisher.json` 에 남긴다.
전체를 다시 색인한 뒤에는 이 뒷마감이 할 일이 없어진다.

## 5. 필드와 가중치

필드마다 TF-IDF 블록을 만들어 가로로 붙이고, 블록마다 스케일 계수를 곱한다.
선형 모델이라 이 계수가 그 필드의 영향력을 직접 조절한다.

| 필드        | 출처               | 분석기      | 기본 가중치 | 이유                                                       |
| ----------- | ------------------ | ----------- | ----------- | ---------------------------------------------------------- |
| `body_word` | summary            | word 1-gram | 1.0         | 주제 분류의 주력. 단독 82.7%                               |
| `body_char` | summary 앞 1,500자 | char_wb 2–4 | 1.0         | 한국어 교착어 대응. 조사가 붙어 단어 매칭이 깨지는 걸 보완 |
| `filename`  | 파일명             | char_wb 2–4 | 1.0         | 단독 82.1%. 저자·시리즈명을 잡는다                         |
| `title`     | ES title           | char_wb 2–4 | 1.0         |                                                            |
| `author`    | ES author          | char_wb 2–4 | 1.0         |                                                            |
| `publisher` | ES publisher       | word 1–2    | **3.0**     | 전집 판정. 다른 필드에 묻히지 않게 올려 둔다               |
| `file_type` | 확장자             | word        | 0.5         | 포맷이 카테고리와 상관이 있다                              |

`class_weight="balanced"` 를 쓴다. `3_판타지` 78,520건 대 최소 30건이라
보정하지 않으면 소수 카테고리를 거의 못 맞힌다.

가중치를 바꾸려면 `config.json` 만 고치고 `train` 을 다시 돌린다. 코드는 안 건드린다.

## 6. 확신도와 판정 거부

선형 모델의 `decision_function` 은 확률이 아니다. 온도로 나눠 softmax 에 넣어
0~1 의 확신도로 바꾼다. 임계값 하나로 판정률과 정답률을 맞바꾼다.

성적은 "전체 정답률" 하나가 아니라 **판정률-정답률 곡선**으로 본다.

## 7. 평가에서 상위 장르를 정답으로 친다

전집은 상위 장르의 부분집합이다. `2_을유세계문학전집` 의 책은 모두 `2_소설외국` 이기도 하다.
모델이 상위 장르를 내놓고 정답이 전집일 때 이를 오답으로 세면 분류 체계의 중복을
모델 결함으로 잘못 읽는다. `SERIES_TO_PARENT`(`config.py`)로 접어서 둘 다 정답으로 친다.

### 웹소설 4종은 합치지 않는다 (2026-09-15 결정)

`3_판타지` `3_무협` `3_여성향` `3_라이트노벨` 은 서로 어휘를 공유해 혼동이 잦다.
실측 2,000건에서 전체 오답 169건 중 72건(42.6%)이 이 4종 내부 혼동이었고,
그중 80.6% 는 정답이 2·3위에 있었다. 4종을 하나로 접으면 정답률이
90.8% → 94.6% 로 오른다.

그래도 접지 않는다. 카테고리마다 작품 수가 많아 실제로 한 디렉토리로 합칠 수 없고,
`SERIES_TO_PARENT` 에 넣으면 판정 결과가 곧 파일 이동 경로라 평가만 좋아지고
운영은 틀어진다.

대신 확신이 없는 것은 판정하지 않고 수동으로 넘긴다. 목표 90/90 을 이미 넘겼으므로
이 선택으로 잃는 것이 없다.

| 구분      | 실측 2,000건         | 코퍼스 235,040건 환산 |
| --------- | -------------------- | --------------------- |
| 자동 분류 | 91.5% (정답률 90.8%) | 약 214,900건          |
| 수동 대상 | 8.6%                 | 약 20,100건           |

수동 대상은 고르게 퍼지지 않는다. `4_사회인류` 70%, `6_처세술리더십창의성` 37%,
`2_수필서간일기` 33% 가 판정 거부인 반면 `3_판타지` 는 3% 다.
자동 분류가 안 되는 쪽은 웹소설이 아니라 논픽션 계열이다.

## 8. 서점은 학습 대상이 아니다

서점 조회는 1초 간격이 필수라 23만 건을 못 돌린다(65일). 후처리 결합으로 둔다.

`calibrate` 가 표본 2,000권에만 서점을 조회하고(3개 서점 × 1초 ≈ 100분),
확신도 구간마다 "모델이 맞은 비율" 과 "서점이 맞은 비율" 을 따로 센다.
서점이 더 나은 구간의 상한 하나가 결합 규칙이다.
서점이 이긴 구간이 없으면 상한은 0 이 되고, 서점을 안 쓴다.

## 9. CLI

`utils/classify_cli.py`. 모든 명령에 `-h` 가 있고, 파라미터마다 범위와
"높이면/낮추면 어떻게 되는지" 를 한글로 적는다.

| 명령                    | 하는 일                                    | 예상 시간                          |
| ----------------------- | ------------------------------------------ | ---------------------------------- |
| `collect`               | ES → `corpus.jsonl`                        | 45초 (`--with-publisher` 는 +30분) |
| `train`                 | 학습 + 홀드아웃 평가 + `model.joblib` 저장 | 10~30분                            |
| `evaluate`              | 저장된 모델의 판정률-정답률 곡선           | 1분                                |
| `calibrate`             | 서점 결합 가중치 학습 (표본 2,000)         | 100분                              |
| `classify <path>`       | 파일 하나 판정 + 근거 출력                 | 즉시                               |
| `reclassify <category>` | 일괄 재분류. 기본은 미리보기               | 가변                               |
| `info`                  | 저장된 모델의 학습 정보                    | 즉시                               |

모델 파일에 학습 시각·설정 지문·홀드아웃 성적을 함께 저장해 되돌릴 수 있게 한다.

## 10. 검증

- 카테고리별 층화 20% 홀드아웃, 학습에서 완전 제외
- `evaluate` 는 학습 때와 같은 난수 씨앗·비율로 같은 홀드아웃을 다시 뗀다
- 제거 대상 함수를 쓰는 기존 테스트는 삭제하고 새 모듈 테스트로 대체
- `pytest tests/` 전체 통과 확인

## 10-1. 첫 학습 결과 (2026-09-14 18:20)

문서 235,040건, 카테고리 79개, 홀드아웃 47,008건. 문자 n-gram 없음, `n_jobs=2`.

| 판정률 | 정답률 | 임계값 |
| ------ | ------ | ------ |
| 50%    | 97.4%  | 0.128  |
| 70%    | 94.3%  | 0.100  |
| 80%    | 92.7%  | 0.082  |
| 90%    | 90.4%  | 0.060  |
| 100%   | 86.4%  | 0.019  |

정답률 90% 를 유지하는 최대 판정률은 **91.6%** 다. 목표 90/90 을 넘겼다.
모델 파일은 165MB, 특징 652,363개, 학습 1,122초.

liblinear 이 `max_iter` 안에 수렴하지 못했다는 경고가 여러 클래스에서 났다.
성적에 얼마나 영향이 있는지는 아직 안 쟀다.

## 10-2. 학습은 별도 systemd 유닛에서 돌린다

학습이 메모리 상한을 넘기면 그 프로세스만 죽는 게 아니었다. `DefaultOOMPolicy=stop`
때문에 systemd 가 tmux pane scope 전체를 정지시켜, 같은 pane 의 개발 세션까지
같이 끊겼다(실측 3회). `user@1000.service` 의 `MemoryMax` 는 12G 다.

그래서 학습을 claude 와 다른 cgroup 에 둔다.

```sh
systemd-run --user --unit=classifier-train \
  -p OOMPolicy=continue -p MemoryMax=10G -p MemorySwapMax=2G \
```

이러면 학습이 OOM 으로 죽어도 세션은 살아남는다.

## 11. 남은 위험

- **이미지 크기**: `scikit-learn`+`scipy` 로 +120MB, `kiwipiepy` 제거로 −135MB,
  어휘 사전 제거로 −2MB, `model.joblib` +160MB. 합계 약 +143MB.
  백엔드 메모리 제한은 4Gi 이고 예측만 컨테이너 안에서 하므로 영향이 없다.
- **모델 파일 크기**: 실측 165MB (79클래스 × 65만 특징). pod 메모리 제한은 4Gi 라
  올릴 수 있다. 저장소 밖에 두므로 git 이 커지는 문제는 없다.
- **학습 메모리**: fit 메모리는 워커 수에 정비례한다. 표본 4만 건(행렬 0.28GB) 실측:

  | n_jobs | fit 시간 | 메모리 증가분 |
  | ------ | -------- | ------------- |
  | 1      | 266초    | 0.37GB        |
  | 2      | 176초    | 0.87GB        |
  | 4      | 131초    | 1.71GB        |
  | 8      | 122초    | 3.23GB        |

  스레드 병렬인데도 는다. liblinear 이 호출마다 자기 자료구조로 옮겨 담기 때문이다.
  비영요소가 4.85배인 23만 건에서 `n_jobs=8` 은 fit 에만 약 15.7GB 를 쓴다.
  기본값을 2 로 내렸다. 8 대비 2.2배 느리고 메모리는 3.7배 적다.
  문자 n-gram 을 켜면 비영요소가 1.2억에서 4.6억으로 늘어 다시 위험해진다.
  같은 장비에서 Elasticsearch 가 3GB, 다른 서비스가 4GB 를 이미 쓰고 있다.

- **소수 카테고리**: `min_per_category` 기본 30 이라 그보다 적은 카테고리는 학습에서
  빠지고 영영 판정 대상이 아니다. 포맷 제한을 풀어 표본을 늘린 뒤 다시 재야 한다.
- **파일 직접 읽기의 포맷 범위**: `reader.read_document_text` 는 `.txt` 와 `.epub` 만
  읽는다. ES 에 없는 PDF·HWP 를 판정하면 본문 없이 파일명·확장자만으로 판정한다.
