# 코퍼스 어휘 사전 기반 자동분류 개선 설계

- 날짜: 2026-09-12
- 상태: 승인됨
- 대상: `backend/book_classifier.py` 자동 분류 판정 로직

## 1. 문제

현재 `evaluate_category_decision()`은 우선순위 캐스케이드다.
먼저 맞은 신호가 곧바로 반환되고, 나머지 신호는 버려진다.

본문 기반 어휘는 `WUXIA/FANTASY/ROFAN/BL/ADULT_KWS` 5개 수작업 상수뿐이다.
`/mnt/data/text`의 실제 카테고리는 145개이고, 그중 5개만 어휘로 덮여 있다.

따라서 두 가지를 만든다.

1. 코퍼스에서 뽑은 카테고리별 어휘 사전 (출현빈도 top 1000 + 고유 단어 세트)
2. 기존 신호와 신규 어휘 점수를 합산하는 가중치 합 판정

## 4. 단어 추출

kiwi 토큰 중 `NNG`, `NNP`, `SL`, `SH`, `SN`만 남긴다.
원문에서 **문자 위치가 붙어 있는** 명사 토큰은 하나로 병합한다.

병합하지 않으면 도메인 용어가 부서진다.

```
입력: 그는 무림맹의 장문인으로서 내공을 운기조식하며 화산파 검법을 익혔다.
병합 전: 무림맹 / 장 / 문인 / 내공 / 운기 / 조 / 식 / 화산 / 파 / 검법
병합 후: 무림맹 / 장문인 / 내공 / 운기조식 / 화산파 / 검법
```

길이 2자 미만 한글 토큰과 3자 미만 라틴 토큰은 버린다.

## 5. 빈도 통계

원시 출현빈도가 아니라 **문서빈도**를 센다.
한 권짜리 거대 파일이 카테고리 통계를 지배하는 것을 막는다.

```
p(c,w)      = w를 포함한 c의 샘플 문서 수 / c의 샘플 문서 수
cf(w)       = p(c,w) >= 0.03 인 카테고리 개수
weight(c,w) = p(c,w) * log(C / cf(w))
```

`top1000(c)`는 `weight` 상위 1000개다.

`사람`, `생각`, `때` 같은 범용 명사는 모든 카테고리에 나타나 `cf(w) = C`가 되고
`log(C/C) = 0`이므로 자동으로 소거된다. 불용어 목록을 따로 두지 않는다.

### 고유 단어 세트

```
exclusivity(c,w) = p(c,w) / Σ_c' p(c',w)
```

`exclusivity >= 0.8` 이고 `p(c,w) >= 0.05` 인 단어를 `unique(c)`로 둔다.
점수 계산에서 배수 1.5를 받는다.

## 6. 샘플링

| 항목 | 값 | 근거 |
|---|---|---|
| 대상 디렉토리 | `^[1-9]_` 패턴만 | `0_telegram` 등 `0_*`는 분류 **입력** 스테이징이지 카테고리가 아님 |
| 카테고리당 최대 | 300 파일, seed 고정 무작위 | 78,027 대 7 불균형 상한 |
| 카테고리당 최소 | 20 파일. 미만이면 사전 미생성 | 통계 신뢰 불가 |
| 파일당 본문 | head 20,000자 + tail 10,000자 | 판권지·후기 편향 완화 |
| 예상 규모 | 약 85 카테고리, 약 25,000 파일, 약 640M자 |
| 예상 소요 | 60~90분 | 위 실측값 기반 |

카테고리별 부분 결과를 캐시해 중단 후 재개할 수 있게 한다.

## 7. 런타임 점수화

1. 대상 파일에서 본문 추출 (기존 `extract_content_head_tail_words` 재사용)
2. 4절 방식으로 토큰화하여 단어 **집합** `W`를 만든다 (집계가 문서빈도 기준이므로 집합이 맞다)
3. 카테고리별 원점수

```
raw(c) = Σ_{w ∈ W ∩ top1000(c)} weight(c,w) × (w ∈ unique(c) ? 1.5 : 1.0)
```

4. 정규화: `lex(c) = raw(c) / max_c raw(c)`, 범위 0~1
5. `raw(최고) < MIN_ABS`이면 신호 없음으로 본다

사전 파일이 없거나 kiwi 로드에 실패하면 스코어러는 빈 결과를 돌려준다.
기존 캐스케이드 동작이 그대로 유지된다.

## 8. 가중치 합 판정

상위 2단계는 조기 반환을 **유지한다**.

1. 파일명 명시 장르 (서점 다수결이 정면 배치되지 않는 한)
2. 서점 2/3 이상 다수결

그 아래를 누적 점수로 바꾼다.

가중치 배정 원칙은 두 가지다.

1. 캐스케이드에서 **단독으로 판정을 내리던 신호는 전부 `ACCEPT_MIN_SCORE` 이상**을 받는다.
   그래야 신호가 하나뿐인 파일의 분류율이 떨어지지 않는다.
   서점 표 하나는 캐스케이드에서도 단독 판정권이 없었으므로 기준 아래에 둔다.
2. 신호 간 순서는 캐스케이드의 우선순위를 따르고,
   인접 신호끼리 `ACCEPT_MARGIN`(1.25배) 이상 벌려 정면 충돌 시 상위 신호가 이기게 한다.

| 기여 신호 | 가중치 |
|---|---|
| 제목 유사도로 검증된 단일 서점 매칭 | 3.0 |
| 단일 서점 매칭 신뢰 | 2.8 |
| `resolve_genre_conflict` 결과 | 2.6 |
| EPUB `dc:subject` → `map_category` | 2.6 |
| TXT 헤더 장르 | 2.6 |
| EPUB `dc:description` → `map_category` | 2.0 |
| TXT 해시태그 1건당 | 2.0 |
| 기존 5대장르 스코어링 | 2.0 ~ 2.5, 점수 비례 |
| 신규 코퍼스 사전 | 0 ~ 2.0, `lex(c)` 비례 |
| 서점 매핑 1건당 | 1.0 |

어휘 사전 신호는 서로 다른 단어가 `LEXICON_MIN_WORDS`(30개) 이상일 때만 낸다.
메타데이터 몇 단어만으로 사전을 돌리면 잡음이 커지기 때문이다.

채택 조건은 두 개를 모두 만족해야 한다.

```
최고점 >= 2.0
최고점 >= 2위 점수 × 1.25
```

미달이면 기존과 동일하게 `None`과 `conflict` / `single_match` / `not_found`를 반환한다.

### method 문자열 보존

우승 카테고리를 지지한 기여자 중 **기존 캐스케이드 순서상 가장 앞선 것**의 이름을 `method`로 쓴다.

```
single_valid_match_resolved > conflict_resolved > single_match > content_metadata > lexicon
```

`reason` 문자열도 해당 기여자의 기존 문구를 유지하고 뒤에 점수 내역을 덧붙인다.
이렇게 하면 기존 테스트 8건의 `method`/`reason` 단정이 그대로 통과한다.
카테고리 **선택**만 가중치 합이 담당한다.

## 9. 검증

파일이 이미 카테고리 디렉토리 안에 있으므로 정답 레이블이 이미 존재한다.

빌더에 홀드아웃 평가 모드를 넣는다.

- 카테고리당 샘플의 20%를 사전 학습에서 제외한다
- 홀드아웃에 대해 기존 캐스케이드와 신규 가중치 합의 top-1 정확도를 비교한다
- 서점 조회는 끄고 파일 내용만으로 판정한다
- 이 측정값을 보고 8절 가중치를 조정한다

단위 테스트는 `tests/test_corpus_lexicon.py`와 `tests/test_category_lexicon.py`에 둔다.
합성 코퍼스를 `tmp_path`에 만들어 `/mnt/data` 의존 없이 돌린다.

## 10. 가정과 남은 위험

- `0_*` 디렉토리를 카테고리에서 제외한다. `0_telegram` 15,876건은 미분류 입력으로 본다.
- 사전 gzip 약 1.5MB를 git에 커밋한다. 생성물이지만 백엔드 런타임이 필요로 한다.
- 백엔드 이미지가 약 135MB 커진다 (kiwipiepy-model 105MB + numpy 30MB).
- `5_서브컬쳐`(10건), `9_격언명언`(7건) 등 꼬리 카테고리는 사전이 생성되지 않는다.
  기존 로직에만 의존한다.
- 코퍼스 디렉토리의 기존 분류 자체에 오류가 있으면 사전이 그 오류를 학습한다.
  홀드아웃 정확도가 낮으면 이 가능성을 먼저 의심한다.
