# 머신러닝 도서 자동 분류기 설계

작성일: 2026-11-07 · 브랜치: `feature/ml-classifier`

## 1. 의도

책 카테고리 관리 서브탭의 "분류 제안"은 frontend와 backend 흐름(제안 → 행별 선택 → 분류 승인 → 이동)이 이미 완성돼 있다.
빠진 것은 판정 근거다. 2026-11-04에 모델·학습 CLI·서점 판정을 지운 뒤로 `libs/classifier`는 trait만 남았고,
backend는 카테고리 매핑 키워드만으로 제안하므로 사실상 아무것도 추천하지 않는다.

이 작업은 세 가지를 만든다.

1. 카테고리별 균등 무작위 표본으로 모델을 학습하는 CLI
2. 그 모델로 책 한 권을 분류하는 `Classify` 구현
3. ISBN 일치·키워드·모델 근거를 카테고리별 가중치 합산 점수로 묶어 추천 1·2를 정하는 backend 판정과, 그에 맞춘 frontend 수정

서점 분류는 나중에 참고 신호로 추가할 예정이다. 그래서 표본 부족으로 인한 오판정은 이번 범위에서 크게 걱정하지 않는다.

## 2. 목표 · 비목표 · 반목표

**목표**

- 분류 제안을 누르면 책마다 합산 점수 내림차순 1·2등이 추천 1·2로 채워진다.
- 학습은 CLI 한 번으로 끝나고, 홀드아웃 정답률을 출력한다.
- 모델 파일은 책 디렉토리와 이미지 밖의 별도 호스트 디렉토리에 두고 pod에 독립적으로 마운트한다. 모델을 바꿔도 이미지 재빌드와 pod 재시작이 필요 없다.

**비목표**

- 서점 판정 부활. `use_bookstore`는 지금처럼 받기만 한다. 서점 근거는 다음 작업에서 이 합산 틀에 근거 하나로 끼운다.
- 가중치 튜닝. 이번에는 초기값만 두고, 실제 값은 서점 근거를 넣을 때 정한다.
- 추천 1 미리 체크. 경계 점수가 가중치와 함께 정해지므로 이번에는 끈다. 나중에 "합산 점수 ≥ 경계면 미리 체크"로 다시 켤 수 있다.
- 카테고리 체계 정리(전집 병합 등). 웹소설 4종은 합치지 않는다는 기존 결정을 유지한다.
- 주기적·자동 재학습.

**반목표 (이러면 실패다)**

- `/mnt/data/text`에 책 이외의 파일(모델, 캐시)을 쓴다.
- 학습 입력에 정답이 새어 들어간다(`file_path`, `category`를 특징으로 쓴다).
- 표본이 균등 무작위가 아니다(ES `random_score`, 앞에서부터 자르기 등).
- 모델 파일이 없을 때 backend가 죽거나 제안 전체가 실패한다.

## 4. 설계

### 4.1 학습 CLI: `utils/classifier_trainer`

**모집단 열거.** ES composite 집계로 대상 문서의 `(inode, 카테고리)`를 끝까지 받는다.
카테고리는 `file_path`의 첫 경로 조각이다. 제외 규칙(3절)을 여기서 적용한다.
카테고리별 실제 권수도 이때 센다.

**표본 추출.** 카테고리마다 seed를 준 ChaCha 난수로 Fisher–Yates 셔플을 하고 앞에서 N개를 자른다.
이는 균등 비복원 추출이다. N보다 작은 카테고리는 전량을 쓴다.
seed를 주지 않으면 OS 난수로 정하고, 출력과 모델 파일에 기록한다.

**문서 수집.** 뽑힌 inode만 `mget`으로 받아 `summary`·`title`·`author`를 가져온다.
`summary`가 비었으면 그 문서를 빼고 건수를 출력한다.

**홀드아웃.** 카테고리별로 표본의 10%(최소 1권, 표본 5권 미만이면 0권)를 떼어 평가에만 쓴다.

**특징.** 사전 없는 해시 특징을 쓴다. 필드마다 다른 namespace로 해시한다.

- `summary`, `title`: 공백 정규화 뒤 글자 2-gram·3-gram
- `author`: 저자 문자열 전체를 토큰 하나로(여러 명이면 쉼표로 나눠 각각)
- 값은 `log(1 + tf)`, 필드별 L2 정규화

**모델.** 다중 클래스 logistic regression(softmax), L2 정규화, 미니배치 경사 하강.
출력이 확률이라 화면의 확신도 표시와 맞는다.

**사전확률 보정.** 균등 표본은 사전확률을 지운다. 추론 때 logit에 `log(실제 권수 / 학습 권수)`를 더해 되살린다.
같은 유사도면 큰 카테고리가 이기고, 표본을 못 채운 카테고리는 자연스럽게 불리하다.
보정 전·후 홀드아웃 정답률을 둘 다 출력한다. 단, 균등 홀드아웃은 실제 분포가 아니므로 보정 후 수치는 실제 분포 가중 정답률로 함께 계산한다.

**참고 지표.** 나중에 미리 체크 경계를 정할 때 쓰도록, 홀드아웃에서 "top-1 확률 ≥ t인 것만 답할 때의 판정률·정답률"을 t = 0.1~0.9 구간으로 출력한다. 모델 파일에는 저장하지 않는다.

**출력.**

- 모델 파일 하나(형식은 4.4)
- 표준 출력: 카테고리 수, 표본 수, seed, top-1·top-2 정답률(보정 전·후), 참고 지표 표, 카테고리별 정답률

**CLI.** 인자 없이 실행하면 `print_usage()`를 출력한다(저장소 규칙).
주요 옵션: `--output <파일>`, `--per-category <N>`(기본 1000), `--seed <u64>`, `--holdout <비율>`.
ES 접속은 기존 `es_client`의 env(`TM_ES_URL` 등)를 쓴다.

### 4.2 추론: `libs/classifier`

`libs/classifier`는 계약 crate로 유지한다. 여기에 ES를 모르는 순수 모델을 더한다.

- 모델 파일 읽기, 특징 추출(학습과 같은 코드), 점수 계산, 사전확률 보정
- `Classify::classify_document(doc)` 구현: `doc`의 `summary`·`title`·`author`로 모든 카테고리의 확률(합 1.0, 사전확률 보정 후)을 점수 순으로 낸다
- 특징 추출 코드는 학습 CLI와 이 crate가 공유한다. 두 벌을 두지 않는다

`classify_path(path)`는 ES 조회가 필요하므로 `libs/book_manager` 쪽 어댑터가 맡는다.
경로 → inode(`book_id_for_path`) → ES 문서 조회 → `classify_document` 순서다.
ES에 없는 파일은 `Err("색인되지 않은 파일")`을 돌려주고, 제안은 모델 없이 계속된다.

### 4.3 합산 판정: `libs/book_manager/src/category_proposer.rs`

**근거 점수.** 근거마다 카테고리별 점수 `p_근거(c)`를 0.0~1.0으로 낸다. 근거는 파일마다 "있음/없음"이 있다.

| 근거 | 있음 조건 | `p(c)` |
|---|---|---|
| ISBN | 파일의 ES 문서에 `isbn`이 있고, 같은 `isbn`의 다른 문서(자기 inode 제외)가 1건 이상 | 카테고리 `c`에 있는 일치 문서 수 / 전체 일치 문서 수 |
| 키워드 | 카테고리 매핑 키워드가 1개 이상 일치 | 카테고리 `c`의 일치 키워드 수 / 전체 일치 키워드 수 |
| 모델 | 모델이 로드됐고 파일이 ES에 색인돼 있음 | 모델 확률 |
| 서점 | 다음 작업 | — |

ISBN 일치 문서 조회는 ES `term` 질의로 한다. 일치 문서가 현재 카테고리에 있으면 현재 카테고리 점수가 올라가 "그대로 둠" 쪽으로 기운다. 중복 도서는 의도된 것이므로 이 근거는 위치 판단에만 쓰고 중복을 지우지 않는다.

**합산.** `score(c) = Σ w_근거 · p_근거(c) / Σ w_근거` (합은 "있음"인 근거만). 결과는 0.0~1.0이다. 근거가 하나도 없으면 후보가 없다.

**초기 가중치 (빌더 판단, 튜닝 안 함).** ISBN 0.6, 키워드 0.25, 모델 0.15. ISBN 하나가 다른 둘을 합친 것보다 크고, 키워드가 모델보다 커서 "ISBN > 키워드 > 모델" 순위를 보존한다. 가중치는 한 곳의 상수 표로 두어 나중에 서점 근거를 더하거나 값을 바꿀 때 그곳만 고친다.

**후보.** `score` 내림차순으로 1·2등을 추천 1·2로 보낸다. 현재 카테고리도 순위에 포함한다. 1등이 현재 카테고리면 frontend는 이미 "제자리"로 처리한다(`isAlreadyInCurrentCategory`). 각 후보는 `category`, `score`, `detail`(근거별 기여 요약, 예: "ISBN 2건 · 모델 0.41")을 싣는다.

**등급 제거.** `ProposalGrade`(`certain`/`unsure`/`unknown`), `is_high_confidence`, `MODEL_CERTAIN_MIN_CONFIDENCE`, 키워드 우선 분기, `fill_second_with_model` 같은 우선순위 분기를 합산 하나로 바꾼다. `BookClassifierApi`의 서점용 메서드(`override_below`, `prefers_bookstore`)와 `min_confidence`·`expected_accuracy`는 쓰는 곳이 없어지면 지운다. 이 정리 범위는 caller를 확인한 뒤 계획에서 확정한다.

**응답 필드.** 항목에서 `grade`, `confidence`, `expected_accuracy`, `source`를 빼고 `score`(1등 점수)와 `classified`(분류 완료 여부)를 더한다. `target_category`는 1등 카테고리로 유지한다(승인 흐름 호환). `model_category`는 모델 단독 1등으로 유지한다.

### 4.3.1 frontend 수정: `CategoryAdmin.jsx`, `ClassifyProposalTable.jsx`

- 추천 1 미리 체크(`grade === "certain"`)를 없앤다.
- "분류 중…" 판단을 `grade == null` 대신 `classified`로 한다.
- 동점 배지를 `grade === "unknown"` 대신 "추천 1·2의 `score`가 같음"으로 판단한다.
- 점수 칸과 정렬은 `expected_accuracy ?? confidence` 대신 `score`를 쓴다. 툴팁 문구도 "합산 점수"로 바꾼다.
- 저장된 이전 제안(`grade` 있는 payload)이 남아 있어도 화면이 깨지지 않아야 한다. `classified`가 없으면 후보가 있는지로 판단한다.

### 4.4 모델 파일과 배포

- 호스트 위치: `/home/terzeron/workspace/tm/models/classifier/model.bin`. `tm`은 `main` 배포용 checkout이다. 학습은 `tm_dev`에서 돌리고 `--output`으로 이 경로에 쓴다.
- 저장소에서는 `models/`를 `.gitignore`에 넣는다. 모델 파일은 커밋하지 않는다.
- `k8s/tm-deployment.yml`: `hostPath`(`type: DirectoryOrCreate`) 볼륨을 `/app/models/classifier`에 `readOnly`로 마운트하고, env `TM_CLASSIFIER_MODEL=/app/models/classifier/model.bin`을 더한다.
- `backend/Dockerfile`은 바꾸지 않는다.
- 핫 리로드: backend는 분류 제안을 시작할 때마다 모델 파일의 수정 시각과 크기를 확인한다. 바뀌었으면 다시 읽고, 같으면 캐시한 `Arc`를 쓴다. 다시 읽기에 실패하면 이전 모델을 계속 쓰고 경고를 남긴다.
- 원자적 교체: 학습 CLI는 같은 디렉토리의 임시 파일에 다 쓴 뒤 rename한다. backend가 반쯤 쓰인 파일을 읽지 않는다.
- 파일이 없거나 처음 읽기에 실패하면 경고 로그를 남기고 모델 근거를 "없음"으로 둔다. 키워드·ISBN 합산은 그대로 돈다.
- 형식: 작은 JSON 헤더(버전, seed, 생성 시각, 카테고리 목록, 실제·학습 권수, 해시 크기) + 가중치 배열. 목표 크기는 50MB 이하다.

## 5. 제약

- Rust만 쓴다. 저장소에 Python이 없다.
- 의존성: `rand`, `rand_chacha` 0.9를 직접 의존으로 추가한다(2026-11-07 사용자 승인). 이미 `Cargo.lock`에 간접 의존으로 있다. 그 밖의 새 의존성은 다시 승인을 받는다.
- 학습 메모리는 수 GB 안이어야 한다. 학습은 사용자 셸에서 foreground로 돌리고, 길면 `systemd-run --user`로 격리한다.
- 테스트는 `tests/rust/<crate>/<모듈>.rs` 1:1, 흐름은 `integration/`. 실행은 `test_runner_rs`로 한다.
- 새 API 엔드포인트는 만들지 않는다. 기존 분류 제안 엔드포인트의 인증 요구사항을 그대로 쓴다.
- frontend 테스트는 vitest다(`cd frontend && npm test`).

## 6. 검증

- 단위: 표본 추출의 균등성(작은 모집단에서 반복 추출해 빈도 확인), 같은 seed의 재현성, 특징 해시의 학습·추론 일치, 사전확률 보정, 근거별 `p(c)`, 합산·정규화(근거 일부만 있음, 하나도 없음, 동점), 모델 없음 경로
- frontend: 미리 체크 없음, `classified` 기반 "분류 중", 점수 동점 배지, 예전 payload 호환
- 통합: 가짜 ES로 학습 → 모델 저장 → 로드 → 분류 제안까지
- 실측: 실제 ES로 N=100과 N=1000을 같은 홀드아웃 규칙으로 학습해 정답률 표를 보고한다
- `cargo clippy --workspace --all-targets`, `kubectl apply --dry-run=client -f k8s/tm-deployment.yml`

## 7. 빌더 재량

- 해시 크기, 학습률, epoch 수, L2 계수: 홀드아웃 결과로 정한다. 모델 크기 50MB 이하를 지킨다.
- crate·모듈 이름은 저장소의 "목적어\_행위자" 규칙을 따른다.
- ES 조회(문서 1건, `isbn` term 질의)를 `EsManagerApi`에 더할지, 기존 검색 메서드로 할지.
- 후보 `detail` 문구.

## 8. 남은 위험

- 정답률은 실측 전까지 모른다. 예전 23만 건 Python 모델의 top-1은 약 79%였다.
- 전집·상위 장르처럼 본문으로 구분이 안 되는 카테고리 쌍은 모델로 풀리지 않는다.
- 모델 마운트는 `hostPath`라 backend pod가 `~/workspace/tm`이 있는 노드에 떠야 한다. 지금 `books-pv`도 `hostPath`라 같은 전제를 이미 쓰고 있다.
- ES에 색인되지 않은 파일은 모델·ISBN 추천을 받지 못한다.
